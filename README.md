# AEM Quicklink Navigator

A browser extension for Adobe Experience Manager (AEM) developers. Save your
AEM environments once, then jump straight to CRXDE, Query Builder, OSGi
console, and 20+ other developer tools with one click, without typing or
bookmarking console URLs by hand.

## Features

- Save Cloud, Classic (AMS/on-prem), and local AEM SDK environments
- Tier-aware links for Cloud environments (Dev/RDE, Stage, Production) so
  you only see consoles that are actually reachable on that tier
- 20+ built-in developer console links: Sites, Assets, Experience Fragments,
  CRXDE Lite, Package Manager, Query Builder, GraphiQL, Sling Distribution,
  Servlet Resolver, Resource Resolver, Components, Dependency Finder,
  Context-Aware Configs, Threads, Health Check, OSGi Config/Bundles, System
  Console, Error Log, Workflows, User Admin, Tools, Cloud Manager
- Search/filter your environment list
- Copy any link to the clipboard with one click
- Duplicate an environment (carries over its custom links, editable URLs)
- Auto-detect: offers to save the current tab if it looks like a new
  AEM environment
- Custom bookmarked links per environment (up to 8)
- Backup and restore your environment list as JSON (Options page)

Everything is stored locally via `chrome.storage`. No data is collected or
sent to any server operated by the developer.

## Installing for development

1. Open `chrome://extensions` (or `edge://extensions`)
2. Enable Developer mode
3. Click "Load unpacked" and select this project's root folder

The extension loads its runtime files (`manifest.json`, `popup.html`,
`options.html`, `background.js`, `js/popup.js`, `js/options.js`) directly
from the project root — no build step is required for local development.

## Project structure

```
manifest.json          extension manifest
popup.html              popup UI (loaded runtime file)
options.html            options page UI (loaded runtime file)
background.js           service worker (loaded runtime file, generated)
js/popup.js             popup logic (loaded runtime file, generated)
js/options.js           options page logic (loaded runtime file, generated)
src/                    readable source for the three generated files above
build.js                obfuscation build script (src/ -> runtime files)
images/                 extension icons (16/32/48/128px)
dist/                   packaged zip(s) and store listing assets
```

## Editing the code

Edit the files under `src/`, not the root-level `background.js` or
`js/popup.js` / `js/options.js` directly — those are generated by the
build step below and get overwritten.

## Building an obfuscated distribution

```bash
npm install
npm run build
```

This runs [`javascript-obfuscator`](https://github.com/javascript-obfuscator/javascript-obfuscator)
against `src/` and writes the obfuscated output to the root-level
`background.js`, `js/popup.js`, and `js/options.js` — the same paths the
manifest and HTML load. Useful for distributing the extension outside an
app store (e.g. a direct download from a blog), where source readability
isn't a concern.

**Do not submit obfuscated code to the Chrome Web Store or Microsoft Edge
Add-ons store** — both explicitly prohibit obfuscated code in developer
policy and will reject or remove the listing. For store submissions,
package the readable `src/` files instead (see `dist/` for a pre-built
readable package).

## Packaging for store submission

A store-ready zip (readable code, `manifest.json` at the zip root) and an
obfuscated zip are both kept under `dist/`. Only the obfuscated zip is
version-controlled; the readable one is rebuilt as needed since `src/` is
already the source of truth in this repo.
